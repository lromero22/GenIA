Este documento describe la estructura y el uso de una base de datos diseñada según el esquema de datos de SuiteCRM. SuiteCRM utiliza un modelo relacional de base de datos para organizar la información en entidades lógicas que representan diversos aspectos de una organización o negocio.
En SuiteCRM, la estructura de la base de datos se basa en una tabla principal que contiene registros principales, como contactos, oportunidades o casos. Estos registros están relacionados entre sí mediante claves primarias y foráneas, permitiendo la representación de relaciones complejas y dependencias de datos.
Además de las tablas principales, SuiteCRM facilita la extensibilidad mediante tablas de extensión, como “nombre_principal_cstm”, donde se pueden almacenar campos personalizados que no están presentes en las tablas principales. Esto proporciona flexibilidad para adaptar la base de datos a las necesidades específicas del negocio sin modificar la estructura base de SuiteCRM.
A lo largo de este documento, se explorarán las entidades fundamentales, los atributos clave y las relaciones que definen la estructura de datos subyacente.
Estructura y Módulos de SuiteCRM
En el contexto de la campaña "Relacionamiento" de Novaventa, utilizamos SuiteCRM para gestionar datos críticos relacionados con los Novaempresarios (NE). El módulo Leads, representado en las tablas Leads y Leads_cstm  , registra información detallada de los NE, incluyendo datos de contacto y categorización dentro de los segmentos de piedras valiosas: esmeralda, diamante y diamante plus. Este módulo es fundamental para identificar y segmentar adecuadamente a los NE según su potencial de negocio.
El módulo calls, con su tabla homónima y la tabla calls_cstm , registra todas las interacciones realizadas con los NE, tales como llamadas, mensajes SMS, WhatsApp y videollamadas. Cada interacción queda documentada con su resultado, proporcionando un registro completo de las comunicaciones y seguimientos realizados en el marco de la campaña.
El módulo Usuarios (conocido como Liker en nuestra empresa), representado en la tabla Users  y users_cstm,  juega un papel crucial como ejecutores de la gestión y los objetivos de la campaña mediante las comunicaciones mencionadas anteriormente 
Además, hemos implementado un módulo personalizado llamado Pedidos, con su tabla lk_pedidos y la tabla lk_pedidos_cstm, diseñada específicamente para registrar ciclo a ciclo los pedidos realizados por los NE. Este módulo también gestiona el estado de los pedidos pendientes, asegurando un seguimiento detallado de las transacciones comerciales y facilitando análisis precisos sobre el rendimiento y la eficacia de las estrategias implementadas.

EJEMPLOS DE PREGUNTAS Y RESPUESTAS:
Pregunta: Dime el nombre, cédula de los novaempresarios que tienen más de 50 semanas de antigüedad 
Query: SELECT leads.last_name, leads_cstm.identificacion_c FROM leads JOIN leads_cstm ON leads.id = leads_cstm.id_c WHERE leads_cstm.antiguedad_c > 50

Pregunta: Traeme el nombre, identificación o cédula, usuario o liker que lo tiene asignado, ciclo y valor del pedido de los leads o novaempresarios para el ciclo 202409
Query: SELECT leads.last_name, leads_cstm.identificacion_c, users.user_name, lk_pedidos.name, lk_pedidos_cstm.valor_venta_sin_iva_c 
FROM leads
JOIN leads_cstm on leads_cstm.id_c=leads.id 
JOIN users on users.id=leads.assigned_user_id 
JOIN leads_lk_pedidos_1_c on leads_lk_pedidos_1_c.leads_lk_pedidos_1leads_ida=leads.id 
JOIN lk_pedidos on lk_pedidos.id=leads_lk_pedidos_1_c.leads_lk_pedidos_1lk_pedidos_idb 
JOIN lk_pedidos_cstm on lk_pedidos_cstm.id_c=lk_pedidos.id
WHERE lk_pedidos.name="202409";

Pregunta: Dime el id del pedido, el ciclo, y el valor de la venta, de todos los ciclos mayores o iguales que 202401
Query: SELECT id_c, ciclo_c, valor_venta_sin_iva_c
FROM lk_pedidos_cstm
WHERE ciclo_c >= '202401';

Pregunta: Dame la cantidad de pedidos y la suma total por ciclos del año 2024
Query: SELECT ciclo_c, COUNT(id_c) AS cantidad_pedidos, SUM(valor_venta_sin_iva_c) AS suma_total_ventas
FROM lk_pedidos_cstm
WHERE ciclo_c LIKE '2024%'
GROUP BY ciclo_c

Pregunta: ¿Cuál es el presupuesto de {novaempresario} para cada ciclo después del {ciclo}?
Query: SELECT lk_pedidos_cstm.ciclo_c, lk_pedidos_cstm.presupuesto_c
FROM leads
JOIN leads_cstm ON leads.id = leads_cstm.id_c
JOIN leads_lk_pedidos_1_c ON leads_lk_pedidos_1_c.leads_lk_pedidos_1leads_ida = leads.id
JOIN lk_pedidos ON lk_pedidos.id = leads_lk_pedidos_1_c.leads_lk_pedidos_1lk_pedidos_idb
JOIN lk_pedidos_cstm ON lk_pedidos_cstm.id_c = lk_pedidos.id
WHERE leads.last_name = {novaempresario} AND lk_pedidos.name >{ciclo};
